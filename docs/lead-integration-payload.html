Tutterfly CRM · Integration Spec

Web-to-Lead JSON Payload

Contract for sending website enquiries into Tutterfly CRM as leads. The structure mirrors the Tutterfly lead form — contact and address fields at the top level, travel details inside industry_data, and the form's Additional Information fields (segment, campaign, experience) inside custom_fields. The endpoint URL and API key (sent as the X-API-Key header) will be shared before go-live.

v4 · final for team July 2026 Audience: website / forms team Method: POST · JSON body
1

Six rules before anything else

Required fieldslast_name, city, state, country + inside industry_data: travel_date, destinations. The CRM rejects the lead if any is missing.
Send names, not IDsexperience, destinations are plain names ("Honeymoon", ["Bali"]). ID resolution happens on the Tutterfly side.
API key goes in the headerEvery request carries X-API-Key: <key> — never a token in the body, never in browser-side code. Server-to-server only.
Phone format+91 9876543210 — country code, space, 10 digits. Bare 10-digit numbers are accepted and treated as +91. Send at least one of email / mobile.
Numbers as numbersNights, pax, adults, children, infants go as JSON integers — 5, not "5".
Do not send source / source_mediumEvery web lead is stamped source = "Website" automatically; source_medium no longer exists. DO send ip — the team derives the enquirer's country from it.

3

Field reference

FieldRequirementNotes
X-API-Key (header)REQUIREDEvery request. Server-to-server only — never expose in browser code. Rotated if leaked. No token in the body.
last_nameREQUIREDMax 100. Single "Name" field? Send the full name here, first_name as "".
city · state · countryREQUIREDAll three enforced by the CRM. The old payload's region is now state.
sourceAUTODo not send — every web lead is stamped "Website" automatically on the CRM side (this also triggers auto-conversion to an opportunity).
industry_data.travel_dateREQUIREDYYYY-MM-DD. Keep the date field required on the form.
industry_data.destinationsREQUIREDArray of destination names, at least one — ["Bali"]. Replaces destinations_name / destination_json / min_country_data.
email · mobileONE OFSend at least one. Mobile: +91 9876543210; bare 10 digits → treated as +91.
salutationOPTIONALMr. Mrs. Ms. Dr. Prof.
phoneOPTIONALAlternate / landline, same format.
company · title · no_employees · websiteOPTIONALB2B info. website = customer's company site, not your landing page. no_employees integer ≥ 1.
street · zipOPTIONALAddress extras.
ipRECOMMENDEDVisitor's IP address — shown on the CRM lead; the sales team derives the enquirer's country from it.
industry_data.no_of_nights · no_of_pax · no_of_adults · no_of_childs · no_of_infantsOPTIONALIntegers ≥ 0, as JSON numbers.
industry_data.is_fixedOPTIONALBoolean — fixed-departure enquiry (the old fixed_departure).
custom_fields.segmentOPTIONALB2C (default) / B2B / CORPORATE. Lead form → Additional Information.
custom_fields.campaign_nameOPTIONALCampaign identifier — lead form's Campaign field.
custom_fields.experienceOPTIONALName: Budget / Standard / Luxury / Ultra-Luxury / Adventure / Honeymoon / Family.

Minimal example

The smallest valid enquiry — every required field, nothing else.

POST /api/v1/integrations/leads
X-API-Key: <API_KEY>
Content-Type: application/json

{
  "lead": {
    "first_name": "",
    "last_name": "Priya Verma",
    "mobile": "+91 9812345678",
    "city": "Mumbai",
    "state": "Maharashtra",
    "country": "India",
    "industry_data": {
      "travel_date": "2026-10-05",
      "destinations": ["Maldives"]
    }
  }
}
Endpoint URL & API key: shared separately before go-live — the key goes in the X-API-Key header on every request. Each submission creates a new lead in the CRM and is auto-converted into an opportunity (201 {"success":true,"lead_id","opportunity_id","converted"}). Errors: 401 bad key · 422 missing required field (readable message) · 429/5xx retry with backoff.
